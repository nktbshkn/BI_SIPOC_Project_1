# 🏨 Отель «Белый пион» — SIPOC и диаграмма прецедентов (TO BE)

## 📌 Описание проекта

Проект посвящён описанию и визуализации целевых (TO BE) процессов цифровой трансформации спа-отеля «Белый пион».

В рамках работы были подготовлены:
- SIPOC-диаграммы ключевых бизнес-процессов
- UML диаграмма прецедентов (Use Case) для системы «О! Отель»
- анализ взаимодействия сотрудников с новой цифровой экосистемой (CRM + PMS)

---

## 🎯 Цель проекта

- Формализовать новые процессы отеля после внедрения CRM-интеграции
- Упростить понимание процессов для сотрудников отдела БиО
- Определить взаимодействие пользователей с системой «О! Отель»
- Подготовить основу для разработки и тестирования системы

---

## 🔷 Часть 1. SIPOC-диаграммы (верхнеуровневые процессы)

SIPOC описывает ключевые бизнес-процессы в формате:

**Suppliers → Inputs → Process → Outputs → Customers**

### Основные процессы, описанные в SIPOC:

#### 1. Создание и управление бронированием
- Поставщики: клиент, CRM
- Входы: данные клиента, предпочтения, доступность номеров
- Процесс: создание / изменение бронирования в «О! Отель»
- Выходы: подтверждённое бронирование
- Клиенты: гость, отдел БиО

---

#### 2. Регистрация и заселение гостя
- Поставщики: CRM, система бронирования
- Входы: данные гостя, история проживания, чёрный список
- Процесс: регистрация заезда
- Выходы: заселённый гость, обновлённый профиль
- Клиенты: гость, отель

---

#### 3. Обработка претензий и обратной связи
- Поставщики: гость, сотрудники БиО
- Входы: жалобы, отзывы, история проживания
- Процесс: обработка претензии + фиксация фидбэка
- Выходы: решение, компенсация, обновление профиля
- Клиенты: гость, CRM, менеджмент

---

#### 4. Управление персонализированными предложениями
- Поставщики: CRM (аналитика)
- Входы: предпочтения, история бронирований, поведение гостей
- Процесс: формирование предложений
- Выходы: персонализированные офферы
- Клиенты: маркетинг, гости

---

#### 5. Назначение компенсаций
- Поставщики: CRM, система претензий
- Входы: жалобы, история гостя, правила компенсаций
- Процесс: подбор компенсации
- Выходы: предложенная компенсация
- Клиенты: сотрудники БиО, гости

---

## 🔷 Часть 2. Диаграмма прецедентов (Use Case)

Диаграмма описывает взаимодействие пользователей с системой «О! Отель» после внедрения CRM-интеграции.

---

## 👥 Акторы системы

- Сотрудник отдела бронирования и обслуживания (БиО)
- Сотрудник отдела маркетинга и продаж (МиП)
- Руководитель МиП
- Владелец отеля
- CRM-система (внешняя система)
- Гость (косвенный актор)

---

## ⚙️ Основные прецеденты системы

### 📌 Работа с бронированием
- Создать бронирование
- Изменить бронирование
- Проверить данные повторного гостя
- Проверить статус «чёрного списка»

---

### 📌 Работа с профилем гостя
- Просмотреть профиль гостя
- Обновить данные гостя
- Просмотреть историю проживания
- Просмотреть предпочтения

---

### 📌 Работа с обратной связью
- Зафиксировать отзыв гостя
- Просмотреть историю фидбэка
- Передать данные в CRM

---

### 📌 Работа с компенсациями
- Получить рекомендацию компенсации
- Назначить компенсацию гостю
- Просмотреть историю компенсаций

---

### 📌 Аналитика и маркетинг
- Просматривать отчёты по гостям
- Сегментировать клиентов
- Формировать персонализированные предложения

---

### 📌 Интеграция систем
- Получать данные из CRM
- Отправлять данные в CRM
- Синхронизировать профиль клиента

---

## 🔄 Ключевая логика системы

После внедрения изменений:
- **CRM становится мастер-системой клиентских данных**
- «О! Отель» — операционная система работы сотрудников
- данные автоматически синхронизируются между системами
- ручной ввод данных минимизируется

---

## 📊 Результат внедрения

- ускорение работы сотрудников БиО
- снижение ошибок при вводе данных
- рост качества персонализации сервиса
- улучшение обработки претензий
- повышение повторных визитов гостей
